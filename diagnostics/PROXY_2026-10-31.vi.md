## Điểm mới liên quan lỗi 3 giây và caption

- Có request `api.revenuecat.com/v1/subscribers/<đã che>` mang User-Agent `Locket/3189`. Điều này xác nhận có hoạt động của Locket trong khoảng capture; chưa xác nhận script Gold đã chạy hoặc app chấp nhận phản hồi.
- Không có bản ghi với host `firebaseremoteconfig.googleapis.com` trong cả ba file. Hai rule `locket_rc` và `locket_rc_us` chỉ khớp endpoint fetch ở host này, project `locket-4252a`. Các log mới chưa ghi nhận request cần thiết để sửa camera/caption qua hai rule đó.
- Có kết nối TCP đến `raw.githubusercontent.com`: 11 ở file `003024`, 1 ở file `003806`. Log không có URL file hay HTTP status tương ứng, nên không chứng minh đã tải thành công đúng bốn script.
- `type=DIRECT` hoặc `result=ROUTING,DIRECT` là thông tin tuyến kết nối trong capture này, không đủ để kết luận MITM bị tắt, chứng chỉ sai hay script thất bại.
- Không tìm thấy chuỗi `[Locket RC ...]` trong các cột lưu trữ. Database này không chứa console output nên không được coi việc thiếu chuỗi đó là bằng chứng script bị lỗi.

## Điều có thể và chưa thể kết luận

Đã xác nhận **các capture mới không ghi nhận request Firebase Remote Config**, dù có request Locket/RevenueCat. Chưa thể khẳng định nguyên nhân duy nhất làm camera 3 giây: app có thể dùng cache, chưa đến lúc fetch, hoặc lưu lượng cần thiết chưa nằm trong phạm vi capture. Cũng chưa xác nhận chứng chỉ đang dùng trên iPhone khớp chứng chỉ trong file local.

Firebase Apple SDK có khoảng chờ tối thiểu giữa các lần fetch, mặc định 12 giờ; ứng dụng có thể đặt giá trị khác. Chưa biết Locket 2.70.0 đặt bao lâu. Đây là một khả năng phù hợp với việc không thấy request, **không phải nguyên nhân đã được chứng minh**. Bỏ `If-None-Match` trong script request chỉ có tác dụng khi app thực sự gửi request. [Tài liệu Firebase iOS](https://firebase.google.com/docs/remote-config/ios/get-started#throttling).

## Bước tiếp theo

1. Giữ một cấu hình Locket hoạt động, xác nhận Global Routing dùng Config và chứng chỉ của cấu hình đó được tin cậy. Xem phần Script URL để xác nhận bốn script tải thành công; kết nối TCP tới GitHub không thay thế được kiểm tra này.
2. Bật ghi log trước khi mở Locket, giữ Shadowrocket hoạt động khi thử. Không hứa rằng đóng/mở app hoặc bật/tắt VPN sẽ ép Firebase fetch ngay; không yêu cầu xóa app, dữ liệu hay mua VPS để thử.
3. Khi thấy request `firebaseremoteconfig.googleapis.com`, kiểm tra path là `/v1/projects/locket-4252a/namespaces/firebase:fetch`, trạng thái giải mã HTTPS và lỗi script nếu ứng dụng hiển thị. Chỉ chia sẻ trạng thái cần thiết, che query và định danh.
4. Nếu script ghi `response rewritten` với `camera=15s` nhưng camera vẫn 3 giây, tiếp tục kiểm tra activate/cache/schema của app. Nếu app không gửi request mới, thay giá trị trong script hoặc phát hành URL mới không tự ép được request đó.

Không thay production code hoặc phát hành thêm phiên bản trong lần phân tích này vì chưa có bằng chứng chỉ ra một lỗi code cụ thể cần sửa.
